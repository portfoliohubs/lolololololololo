## 🎯 مدخل إلى لغة الحوار عبر الإنترنت
في الدرس السابق (3-1)، تعلمنا أن تطبيق الويب يتكون من ثلاث طبقات: واجهة أمامية، واجهة خلفية، وقاعدة بيانات.
ولكن السؤال الجوهري الذي يطرح نفسه الآن هو: **كيف تتحدث هذه الطبقات مع بعضها البعض عبر الإنترنت؟ وما هي القواعد والبروتوكولات ولغات التفاهم التي تنظم هذا الحوار الرقمي السريع؟**
في هذا الدرس، سنكتشف أسرار **نموذج العميل والخادم**، ونتعرف على بروتوكولات **HTTP و HTTPS**، ونفك شفرة **أساليب الطلب (GET / POST)** و**رموز الحالة (Status Codes)**، ونتعلم كيف تتبادل الأنظمة البيانات عبر **واجهات الـ API** وصيغة **JSON**.

## 1. نموذج العميل والخادم (Client / Server Model)
يقوم الاتصال في الويب على طرفين رئيسيين يتعاونان في دورة تسمى **"دورة الطلب والاستجابة" (Request-Response Cycle)**:

```
[ 💻 العميل (Client) ]   ------ (1) إرسال طلب (Request) ------>   [ ⚙️ الخادم (Server) ]
(متصفح الويب / الهاتف)  <----- (2) إرجاع استجابة (Response) -----  (خادم الويب المعالج)
```

### التعريفات المنهجية المعتمدة:
1. **العميل (Client):** هو جهاز أو برنامج يرسل طلباً (Request) إلى خدمة أخرى لطلب بيانات أو معالجة.
   - *أمثلته المألوفة:* متصفح الويب على حاسوبك (مثل Chrome أو Firefox)، أو تطبيق على هاتفك الذكي.
2. **الخادم (Server):** هو الجانب الذي يستقبل الطلبات من العملاء، ويعالجها، ويعيد الاستجابات (Responses) بالبيانات أو النتائج.
3. **دورة الطلب والاستجابة:** يرسل العميل طلباً ➔ يستلمه الخادم ويعالجه ➔ يعيد الخادم استجابة للعميل.

## 2. بروتوكولات نقل البيانات: المقارنة بين HTTP و HTTPS

لضمان فهم الطرفين لبعضهما، يحتاج الاتصال إلى "لغة مشتركة" تسمى **البروتوكول (Protocol)**:

| وجه المقارنة | بروتوكول HTTP | بروتوكول HTTPS |
| :--- | :--- | :--- |
| **الاسم الكامل** | Hypertext Transfer Protocol<br>(بروتوكول نقل النص التشعبي) | Hypertext Transfer Protocol Secure<br>(بروتوكول نقل النص التشعبي الآمن) |
| **آلية العمل** | بروتوكول قياسي لتبادل الرسائل والبيانات بين العميل والخادم على الويب. | استخدام بروتوكول HTTP ولكن عبر **اتصال مشفر وآمن بواسطة بروتوكول TLS**. |
| **مستوى الأمان والتشفير** | **غير مشفر (نص مكشوف Plaintext):** يمكن لأي متجسس على الشبكة قراءة البيانات وتعديلها بسهولة. | **مشفر بالكامل بواسطة TLS (Transport Layer Security):** يضمن سرية الاتصال وسلامته ومصادقة هوية الخادم. |
| **عنوان الموقع (URL)** | يبدأ بـ `http://` | يبدأ بـ `https://` وتظهر علامة القفل الآمن 🔒 |
| **الاستخدام الموصى به** | صفحات ثابتة عامة لا تحتوي على أي معلومات حساسة (أصبح شبه مهجور حالياً). | **إلزامي** في صفحات تسجيل الدخول، المعاملات المالية، والمتاجر الإلكترونية، وحماية الخصوصية. |

### 🔒 ما الذي يوفره بروتوكول TLS داخل HTTPS؟
1. **مصادقة الخادم (Server Authentication):** التأكد من أنك تتصل بالخادم الحقيقي للموقع وليس بموقع مزيف.
2. **حماية سرية الاتصال (Confidentiality):** تشفير محتوى الرسائل بحيث لا يستطيع أي طرف ثالث قراءتها.
3. **حماية سلامة الاتصال (Integrity):** منع أي متجسس من التلاعب بالبيانات أو تعديلها أثناء انتقالها في السلك أو الهواء.

## 3. أساليب طلب HTTP: الفرق بين GET و POST (HTTP Request Methods)
عندما يرسل العميل طلباً للخادم، يجب أن يحدد **طريقة الطلب (HTTP Method)** ليوضح للخادم **"نوع العملية المطلوبة"**:

| طريقة الطلب | الدور والاستخدام الأساسي | أمثلة تطبيقية منهجية |
| :---: | :--- | :--- |
| **GET** | يُستخدم عادة **لطلب مورد أو بيانات من الخادم** (استرجاع وقراءة دون إحداث تعديل في خادم الويب). | - عرض صفحة ويب جديدة.<br>- استرجاع نتائج البحث عن كلمة معينة.<br>- تنزيل ملف PDF أو صورة.<br>- جلب بيانات الطقس اليومية. |
| **POST** | يُستخدم عادة **لإرسال بيانات إلى الخادم ليعالجها** (إجراء تعديل أو حفظ أو إنشاء سجل جديد). | - إرسال معلومات تسجيل الدخول (اسم المستخدم وكلمة المرور).<br>- إرسال محتويات نموذج اتصال (Contact Form).<br>- نشر تعليق أو صورة على شبكة تواصل.<br>- إرسال تفاصيل بطاقة الائتمان لإتمام عملية شراء. |

## 4. رموز حالة HTTP النموذجية (HTTP Status Codes)
عندما يعيد الخادم استجابته إلى العميل، فإنه يرفق معها **رقماً من ثلاثة خانات** يُسمى **رمز الحالة (Status Code)**، ليخبر المتصفح فوراً بنتيجة معالجة الطلب:

```
+------------------------------------------------------------------------------------+
| 🟢 200 OK: تم بنجاح!                                                               |
| 🟡 404 Not Found: المورد غير موجود (راجع الرابط الذي كتبته يا عميل).              |
| 🔴 500 Internal Server Error: عطل داخلي في الخادم (العطل عند المخدم وليس العميل).  |
+------------------------------------------------------------------------------------+
```

### تفصيل الرموز المعتمدة في كتاب الوزارة:
1. **رمز 200 (Success / OK):**
   - **المعنى:** تمت معالجة الطلب بنجاح تام، والخادم يرسل البيانات المطلوبة في الاستجابة.
2. **رمز 404 (Not Found):**
   - **المعنى:** المورد المطلوب غير موجود بهذا العنوان (مثل صفحة محذوفة أو رابط به خطأ إملائي من المستخدم).
   - **الجهة المسؤولة عن المشكلة:** جهة العميل (Client-side issue) بسبب طلب عنوان غير صحيح.
3. **رمز 500 (Internal Server Error):**
   - **المعنى:** حدث خطأ داخلي غير متوقع في الخادم منعه من إكمال الطلب (مثل فشل كود برمجي أو عطل في قاعدة البيانات).
   - **الجهة المسؤولة عن المشكلة:** جهة الخادم (Server-side issue) والرمز لا يحدد وحده السبب التفصيلي.

## 5. واجهات برمجة التطبيقات (API) وصيغة البيانات (JSON)

### ما هي واجهة برمجة التطبيقات (API)؟
**واجهة برمجة التطبيقات (API - Application Programming Interface)** هي **مجموعة قواعد واضحة وعقد برمجي** يتيح لبرنامج طلب بيانات أو وظائف من برنامج آخر أو خدمة أخرى عبر الشبكة.
- *مثال:* الواجهة الأمامية ترسل طلبات عبر الـ API إلى الواجهة الخلفية لتستقبل البيانات منها، أو موقع حجز طيران يستعين بـ API من شركات الطيران لمعرفة مواعيد الرحلات وأسعارها.

### صيغة تبادل البيانات المهيكلة (JSON):
تعيد واجهات الـ API البيانات غالباً بصيغة تسمى **JSON (JavaScript Object Notation)**.
- **خصائص JSON:**
  - صيغة نصية خفيفة وسهلة القراءة للبشر وتفهمها الحواسيب واللغات البرمجية المتعددة بسرعة فائقة.
  - تمثل البيانات المهيكلة باستخدام أزواج من **المفاتيح والقيم (Key : Value Pairs)** والمصفوفات (Arrays).

### مثال تطبيقي لكود JSON (من كتاب الوزارة):
```json
{
  "city": "Cairo",
  "temperature": 31
}
```
- `"city"` هو **المفتاح (Key)**، وقيمته المقابلة هي النص `"Cairo"`.
- `"temperature"` هو **المفتاح (Key)**، وقيمته المقابلة هي الرقم `31`.

## 6. ورش التفكير الهندسي والتطبيقات العملية

### ورشة نظام المدرسة السحابي:
- **الموقف:** مدرسة تريد بناء تطبيق ويب يتيح للطلاب تسجيل الدخول، وعرض جدولهم الدراسي، وتحميل سجل درجاتهم كملف PDF.
- **تحديد أساليب الطلب والبروتوكول المناسب:**
  1. **إرسال نموذج تسجيل الدخول:** ➔ يستخدم أسلوب **`POST`** لأنها بيانات حساسة تُرسل للخادم للتحقق منها ومعالجتها.
  2. **تحميل سجل درجات الطلاب (PDF):** ➔ يستخدم أسلوب **`GET`** لأنه طلب استرجاع وتنزيل مورد موجود.
  3. **طلب الجدول الدراسي لليوم من نظام مدرسة أخرى:** ➔ يتم عبر **واجهة برمجة تطبيقات (API)** باستخدام أسلوب **`GET`**، وتعود البيانات غالباً بصيغة **JSON**.
  4. **اختيار البروتوكول لصفحة تسجيل الدخول:** ➔ **`HTTPS` إلزامي** لأن تشفير TLS يمنع المتجسسين على شبكة المدرسة أو الإنترنت من قراءة كلمات مرور الطلاب أو التلاعب بسجلاتهم.

### ورشة خدمة الطقس العالمية:
- خدمة تقدم API لتوقعات الطقس:
  - العميل يرسل طلب **`GET`** لاسترجاع درجات الحرارة.
  - الخدمة تستخدم **`HTTPS`** لضمان عدم تلاعب أي وسيط بالبيانات الجوية.
  - تعيد الخدمة البيانات بصيغة **`JSON`** لأنها نصية مهيكلة تسهل على الواجهة الأمامية استخراج درجات الحرارة وعرضها برمجياً في المتصفح.

## 7. ورشة السؤال المقالي الوزاري المتوقع [6 درجات]

### نص السؤال الوزاري الرسمي:
> *"اشرح خطوة بخطوة ما يحدث عندما يطلب المتصفح صفحة ويب ويستجيب الخادم. [6 درجات] أشر إلى: العميل، الطلب، طريقة طلب HTTP، الاستجابة، رمز حالة HTTP."*

### نموذج الإجابة المعتمد الكامل (للحصول على 6/6):
- **1. دور العميل وتوليد الطلب [درجة ونصف]:**
  - يبدأ المتصفح بوصفه **العميل (Client)** العملية عندما يكتب المستخدم عنوان الصفحة أو ينقر على الرابط، فيقوم بإنشاء وإرسال **طلب HTTP (Request)** عبر الشبكة إلى خادم الويب المستضيف.
- **2. تحديد طريقة طلب HTTP [درجة ونصف]:**
  - يتضمن الطلب **طريقة طلب HTTP (مثل GET)** لتوضيح نوع العملية المطلوبة، وهي هنا طلب استرجاع وتنزيل محتوى صفحة الويب من الخادم.
- **3. استلام الخادم ومعالجة الطلب [درجة واحدة]:**
  - يستقبل **الخادم (Server)** الطلب، ويقوم بفحصه والبحث عن صفحة الويب المطلوبة في نظامه، وتجهيز الملفات المرتبطة بها (مثل HTML و CSS).
- **4. إرسال الاستجابة ورمز حالة HTTP [درجتان]:**
  - يُعيد الخادم **استجابة (Response)** عبر الشبكة إلى المتصفح تتضمن **رمز حالة HTTP (مثل 200 OK)** لإعلام العميل بنجاح المعالجة، ويرفق معها محتوى صفحة الويب ليقوم المتصفح برسمها وعرضها للمستخدم.
  - *(وإذا لم يجد الخادم الصفحة، يعيد رمز حالة **404 Not Found**)*.
