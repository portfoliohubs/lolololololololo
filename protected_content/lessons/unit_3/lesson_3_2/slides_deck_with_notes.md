## 📑 الشريحة 3: نموذج العميل والخادم ودورة الطلب والاستجابة
- **محتوى الشريحة المرئي:**
  - رسم تخطيطي متحرك:
    - [ 💻 العميل (Client) ] ── (1) إرسال طلب (Request) ──► [ ⚙️ الخادم (Server) ]
    - [ 💻 العميل (Client) ] ◄── (2) إرجاع استجابة (Response) ── [ ⚙️ الخادم (Server) ]
  - العميل: جهاز أو برنامج يطلب البيانات أو المعالجة (مثل متصفح الويب وتطبيق الهاتف).
  - الخادم: الجانب الذي يستقبل الطلبات، يعالجها، ويعيد الاستجابات.
  - دورة الطلب والاستجابة: التبادل المنظم الذي تقوم عليه معظم تطبيقات الويب.
- **ملاحظات الإلقاء الصوتي لدكتور مايكل:**
  > *"بصوا معايا للشاشة: الويب كله قايم على الحوار المنظم ده. على اليمين عندك العميل (Client)، وده ممكن يكون جهازك، متصفح Chrome أو Firefox، أو تطبيق على تليفونك. العميل مبيعرفش يطبخ البيانات بنفسه، فبيبعت طلب رسمي اسمه (Request). على الناحية التانية عندنا الخادم (Server)، وده جهاز المخدم العملاق اللي قاعد مستني، بيستلم الطلب، يعالجه في كوده البرمجي، ويجهز الرد ويرجعه في صورة استجابة (Response). الدورة دي اسمها دورة الطلب والاستجابة (Request-Response Cycle)، وهي دقات قلب الإنترنت."*

## 📑 الشريحة 4: بروتوكول HTTP مقابل HTTPS ومعركة التشفير (TLS)
- **محتوى الشريحة المرئي:**
  - جدول مقارنة احترافي ذو لونين:
    - **HTTP (Hypertext Transfer Protocol):** بروتوكول قياسي لتبادل الرسائل | نص مكشوف (Plaintext) | غير آمن.
    - **HTTPS (Hypertext Transfer Protocol Secure):** بروتوكول HTTP محمي باتصال TLS آمن | مشفر بالكامل | آمن 🔒.
  - ثلاثية الحماية التي يوفرها TLS (Transport Layer Security):
    1. **مصادقة الخادم (Server Authentication):** التأكد من هوية الموقع الأصلي.
    2. **حماية سرية الاتصال (Confidentiality):** تشفير محتوى الرسائل ضد التنصت.
    3. **حماية سلامة الاتصال (Integrity):** منع أي متجسس من التلاعب أو تعديل البيانات أثناء النقل.
- **ملاحظات الإلقاء الصوتي لدكتور مايكل:**
  > *"عشان الاتصال ده يحصل، محتاجين لغة موحدة، وده اللي بنسميه البروتوكول. زمان كان عندنا HTTP العادي. HTTP ده عامل بالظبط زي كارت بوستال بريدي مكشوف؛ أي حد في السنترال أو الشبكة يقدر يقرأ اللي مكتوب فيه بسهولة! عشان كده ظهر المنقذ: HTTPS. حرف الـ S هنا يعني Secure. هو نفس الـ HTTP لكنه مسافر جوة نفق مشفر بتقنية TLS (Transport Layer Security). الـ TLS بيعمل تلات حاجات ذهبية: بيأكدلك إنك بتكلم السيرفر الحقيقي مش موقع نصاب (مصادقة)، بيقفل البيانات في خزنة مشفرة محدش يقدر يقرأها (سرية)، وبيمنع أي متجسس من إنه يغير رقم في حسابك أو يعدل بياناتك في الطريق (سلامة)."*

## 📑 الشريحة 5: أساليب طلب HTTP: المعركة بين GET و POST
- **محتوى الشريحة المرئي:**
  - **طريقة طلب HTTP (Request Method):** توضح للخادم "نوع العملية المطلوبة".
  - **أسلوب GET:**
    - الاستخدام: طلب مورد أو استرجاع بيانات من الخادم دون تعديل.
    - أمثلة منهجية: عرض صفحة ويب، استرجاع نتائج البحث، تنزيل صورة أو ملف.
  - **أسلوب POST:**
    - الاستخدام: إرسال بيانات إلى الخادم ليعالجها (تعديل أو حفظ أو تسجيل).
    - أمثلة منهجية: إرسال معلومات تسجيل الدخول (كلمات المرور)، إرسال محتويات النماذج، نشر المنشورات والمعاملات المالية.
- **ملاحظات الإلقاء الصوتي لدكتور مايكل:**
  > *"العميل لما بيبعت طلبه، لازم يقول للسيرفر: 'هو أنا جاي أطلب إيه بالظبط؟'. وده بنسميه أسلوب الطلب (Method). عندنا أسلوبين هما الأشهر في الوجود:
  الأول هو GET: تخيل إنك رايح المكتبة بتستعير كتاب؛ أنت بتقرأ وتسترجع مورد موجود من غير ما تغير حاجة في رفوف المكتبة، زي ما بتفتح صفحة ويب أو بتدور على منتج.
  أما الثاني فهو POST: ده عامل زي ما تروح البنك وتملأ استمارة طلب قرض فيها بياناتك الحساسة ومرتبك وبصمتك؛ أنت بتبعت بيانات جديدة عشان السيرفر يعالجها ويتأكد منها ويحفظها، زي كتابة الباسورد في شاشة الدخول أو ملء استمارة تسجيل!"*

## 📑 الشريحة 6: رموز حالة HTTP (إشارات المرور الرقمية 200, 404, 500)
- **محتوى الشريحة المرئي:**
  - بطاقات دائرية مضيئة:
    - 🟢 **200 OK (نجاح):** تمت معالجة الطلب بنجاح تام وتم إرجاع المورد.
    - 🟡 **404 Not Found (غير موجود):** المورد المطلوب غير موجود بهذا العنوان (خطأ في جهة العميل).
    - 🔴 **500 Internal Server Error (خطأ خادم):** حدث خطأ داخلي في الخادم منعه من إكمال الطلب (خطأ في جهة المخدم؛ ولا يحدد الرمز وحده السبب التفصيلي).
- **ملاحظات الإلقاء الصوتي لدكتور مايكل:**
  > *"السيرفر لما بيخلص شغل، مش بيرد عليك بكلام عشوائي، بيبعت مع الرد رقم كودي ثلاثي اسمه رمز الحالة (Status Code). دي إشارات المرور بتاعت الإنترنت:
  لو شوفت 200 OK، يبقى الإشارة خضرا وكله تمام وطلبك اتنفذ بنجاح.
  لو شوفت 404 Not Found، الإشارة صفرا وبتقولك: 'يا فندم العنوان اللي طلبته مش موجود عندي'، زي صفحة اتمسحت أو حرف كتبته غلط في الرابط، والمشكلة هنا عند العميل.
  أما لو ظهرلك الكابوس 500 Internal Server Error، فالإشارة حمرا وبتقولك إن الخادم نفسه جواه عطل غير متوقع، الكود ضرب أو قاعدة البيانات وقعت، والرمز لوحده مبيقولكش إيه السبب التفصيلي لكن بيحددلك إن العيب في مطبخ السيرفر!"*

## 📑 الشريحة 7: واجهات برمجة التطبيقات (API) وصيغة البيانات (JSON)
- **محتوى الشريحة المرئي:**
  - **واجهة برمجة التطبيقات (API):** مجموعة قواعد واضحة تسمح لبرنامج بطلب بيانات أو وظائف من برنامج آخر أو خدمة أخرى.
  - قد ترسل الواجهة الأمامية طلبات إلى خدمة خلفية عبر API وتستقبل منها البيانات.
  - **صيغة JSON (JavaScript Object Notation):**
    - صيغة نصية شائعة لتمثيل وتبادل البيانات المهيكلة باستخدام كائنات ومصفوفات وقيم بسيطة.
    - خفيفة وسهلة القراءة للبشر ومدعومة من كافة لغات البرمجة.
  - كود توضيحي (من كتاب الوزارة):
    ```json
    {
      "city": "Cairo",
      "temperature": 31
    }
    ```
    - المفتاح: `"city"` ➔ القيمة: `"Cairo"`
    - المفتاح: `"temperature"` ➔ القيمة: `31`
- **ملاحظات الإلقاء الصوتي لدكتور مايكل:**
  > *"طب السيرفر هيرد على المتصفح بإيه؟ لو تطبيق حديث بيبعت بيانات خام، بنحتاج واجهة تفاهم مشتركة اسمها API (Application Programming Interface). ده العقد والاتفاق اللي بيخلي البرامج تتكلم مع بعضها. والـ API بيعشق صيغة نصية خفيفة اسمها JSON (JavaScript Object Notation). بصوا للمثال اللي على الشاشة من كتاب الوزارة: كائن فيه مفتاح (Key) اسمه city وقيمته (Value) هي Cairo، ومفتاح تاني اسمه temperature وقيمته 31. نص منظم، خفيف، أي لغة برمجة في العالم تقدر تقراه في لمح البصر!"*

## 📑 الشريحة 9: حل السؤال المقالي الوزاري المتوقع [6 درجات كاملة]
- **محتوى الشريحة المرئي:**
  - **السؤال الوزاري:** اشرح خطوة بخطوة ما يحدث عندما يطلب المتصفح صفحة ويب ويستجيب الخادم. [6 درجات]

    1. **العميل وتوليد الطلب [1.5 درجة]:** المتصفح يمثل العميل ويرسل طلب HTTP عند كتابة العنوان أو نقر الرابط.
