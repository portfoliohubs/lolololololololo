## 1. بطاقة الهوية التعليمية للدرس
* **المسار الدراسي:** الوحدة الخامسة: جمع البيانات وتنقيتها (Data Collection and Cleaning).
* **رمز الدرس:** `LESSON_5_3` (الدرس الثالث والختامي للوحدة الخامسة).
* **عنوان الدرس:** البيانات المفتوحة وواجهات برمجة التطبيقات (Open Data and APIs).
* **الموجه الأكاديمي:** د. مايكل (دكتوراه علوم الحاسب، مؤسس منصة parmaga التعليمية).
* **الشعار البيداغوجي:** *"البيانات المفتوحة كنز معرفي عام، وواجهات برمجة التطبيقات (APIs) هي الأنابيب الذكية التي تضخ هذا الكنز إلى برامجك... لكن الحرية لا تعني الفوضى: شروط الاستخدام والاستشهاد العلمي هما ميثاق شرف المحلل المحترف!"*

## 3. المعمارية الهيكلية لصفحة الدرس (Hexagonal UI Architecture)

```
====================================================================================
               [BANNER] د. مايكل: استوديو واجهات البرمجة والبيانات المفتوحة
====================================================================================
 [1] محطة الانطلاق (The Concept Launchpad)
     - تشبيه خط أنابيب المياه والعداد الذكي (The Digital Pipeline Analogy)
     - الفرق الحاسم: "متاح مجاناً للرؤية" vs "مرخص ومفتوح لإعادة الاستخدام"
     - شروط الاعتماد الأربعة (المصدر، الجودة، طريقة الوصول، الترخيص)
------------------------------------------------------------------------------------
 [2] بوابة العمالقة الثلاثة (The Big Three Open Data Portals)
     - بطاقة تفاعلية 1: World Bank Open Data (الناتج القومي، التعليم، الصحة الدولية)
     - بطاقة تفاعلية 2: UN Data (المؤشرات التنموية متعددة الوكالات)
     - بطاقة تفاعلية 3: Kaggle (مجموعات المسابقات وبناء نماذج الذكاء الاصطناعي)
------------------------------------------------------------------------------------
 [3] مختبر محاكاة API التفاعلي (Live API Inspector Sandbox)
     - العميل (Client) -> الطلب (Request to Endpoint URL) -> الخادم (Server)
     - مستعرض استجابة JSON الحي (JSON Viewer: Object, Arrays, Key/Value)
     - محاكي معالجة الأخطاء وحدود الطلبات (Rate Limiting 429 & Client Handling)
------------------------------------------------------------------------------------
 [4] ميثاق الشرف والاستشهاد (Ethics, Licenses & Citations Lab)
     - العناصر الأربعة للاستشهاد الأكاديمي النموذجي (Citation Generator)
     - الحقيقة الذهبية: ذكر المصدر لا يعصم البيانات من الأخطاء بل يتيح المراجعة!
------------------------------------------------------------------------------------
 [5] ورشة المهندس المحترف (Engineer Project & Minister Exam Studio)
     - مشروع الإنترنت في مصر والدول المجاورة (ص 125)
     - تفكيك وحل سؤال الامتحان الوزاري (6 درجات)
------------------------------------------------------------------------------------
 [6] التقييم التكويني وخاتمة الوحدة الخامسة (Unit 5 Capstone Assessment)
     - بنك الأسئلة المائة (100 MCQs)
     - البطاقات الذكية (20 Flashcards)
     - احتفالية إنهاء الوحدة الخامسة والانتقال للوحدة السادسة!
====================================================================================
```

## 4. تصميم العناصر التفاعلية والمعامل الافتراضية
* **المعمل التفاعلي الرئيسي `OpenApiSandbox.tsx`:**
  - واجهة تحاكي بيئة تطوير (Postman-Lite) تتيح للطالب اختيار مزود بيانات (World Bank API أو Weather API).
  - تحديد نقطة النهاية `Endpoint` والضغط على زر `Send GET Request`.
  - معاينة تدفق الطلب من العميل إلى الخادم ورؤية الاستجابة في الوقت الفعلي بصيغة `JSON` ملونة ومرتبة.
  - تجربة سيناريو الخطأ: تجاوز حد الطلبات (Rate Limit Exceeded) أو انقطاع الخدمة وملاحظة كيف يتعامل كود التطبيق الذكي مع الاستجابة.
* **أداة توليد الاستشهاد العلمي `CitationBuilder.tsx`:**
  - إدخال بيانات مجموعة البيانات (اسم الناشر، اسم المجموعة، رابط URL، تاريخ الوصول).
  - توليد الاقتباس المعياري الصالح للأبحاث والتقارير الفنية تلقائياً، مع تنبيه تحليلي: *"تذكر أن الاقتباس يحمي أمانتك العلمية ويمكّن زملاءك من مراجعة تحليلك، لكنه لا يعفيك من تدقيق جودة البيانات!"*
