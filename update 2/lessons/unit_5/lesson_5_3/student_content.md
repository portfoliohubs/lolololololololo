## 🧭 الفكرة الرئيسية للدرس (The Core Thesis)
تأتي البيانات المفتوحة من مزودين موثوقين (مثل World Bank Open Data و UN Data و Kaggle). يمكن تنزيلها مباشرة من متصفح الويب كملفات، أو جلبها آلياً بواسطة برنامج عبر **واجهة برمجة تطبيقات (API)** — حيث يرسل العميل طلباً إلى عنوان محدد يُسمى **نقطة النهاية (Endpoint)**، ويعيد الخادم استجابة تحتوي البيانات (غالباً بصيغة **JSON**). ولكن تذكر القاعدة الذهبية: **لكل مجموعة بيانات شروط استخدام وترخيص يجب اتباعها، ومصدر يجب الإشارة إليه بالاستشهاد العلمي الدقيق، مع تقييم جودة البيانات ومنهجيتها بصورة مستقلة.**

## 📚 المحور الأول: ما هي البيانات المفتوحة؟ ولماذا المجانية وحدها لا تكفي؟

### 1. مفهوم الانفتاح الحقيقي (Openness vs. Free Access)
قد تجد على شبكة الإنترنت جدولاً منشوراً على موقع إلكتروني يمكنك قراءته مجاناً دون دفع أموال. هل هذا يعني تلقائياً أنه "بيانات مفتوحة"؟
**الإجابة الحاسمة: لا!**
* **المجانية أو الإتاحة العامة (Free/Public Access):** تعني فقط أنك قادر على قراءة البيانات أو رؤيتها دون رسوم اشتراك.
* **البيانات المفتوحة (Open Data):** تتطلب **ترخيصاً واضحاً أو شروطاً صريحة (Explicit License / Terms)** تسمح لك صراحة بثلاثة حقوق مقدسة:
  1. **الوصول (Access):** حق الوصول إلى البيانات بصيغة قابلة للاستخدام ومعالجتها حاسوبياً.
  2. **إعادة الاستخدام (Reuse):** حق إدخال البيانات في تحليلاتك أو دمجها مع مجموعات بيانات أخرى أو بناء تطبيقات عليها.
  3. **إعادة التوزيع (Redistribution):** حق نشر النتائج ومشاركة البيانات أو الرسومات المشتقة منها مع العامة أو في أبحاثك.

```
+-------------------------------------------------------------------------------+
|                      المثلث الذهبي للبيانات المفتوحة                          |
|                                                                               |
|             [1] حق الوصول             <--->          [2] حق إعادة الاستخدام   |
|         (Access to Raw Data)                       (Process & Build Upon)     |
|                                     \       /                                 |
|                                      \     /                                  |
|                                       v   v                                   |
|                             [3] حق إعادة التوزيع                              |
|                              (Share & Distribute)                             |
|                                                                               |
|       *كل هذا مشروط بإطار قانوني وأخلاقي: (ترخيص معلن + شروط استخدام واضحة)*     |
+-------------------------------------------------------------------------------+
```

### 2. الفحص الرباعي قبل لمس أي مجموعة بيانات (The 4-Pillar Checklist)
عندما تقرر بصفتك محلل بيانات استخدام أي بيانات مفتوحة، يفرض عليك كتاب الوزارة (ص 120) التحقق الصارم من **أربعة أمور حاسمة**:
1. **المصدر (Source):** من هي الجهة الناشرة؟ هل هي منظمة رسمية ذات سمعة علمية موثوقة (مثل البنك الدولي أو الأمم المتحدة)؟ أم جهة مجهولة الهوية؟
2. **الجودة (Quality):** هل البيانات محدثة؟ هل تم جمعها وفق منهجية علمية شفافة؟ ما نسبة القيم المفقودة بها؟
3. **طريقة الوصول (Access Method):** هل تتيح الجهة تنزيل الملفات بصيغ مهيكلة (CSV, Excel)؟ أم توفر واجهة برمجة تطبيقات (API) للبث والربط البرمجي المباشر؟
4. **شروط الاستخدام أو الترخيص (License & Terms of Use):** ما الذي يُسمح لك بفعله قانونياً؟ هل يُشترط الاستخدام غير التجاري؟ وما هي الصيغة المطلوبة لذكر المصدر؟

> 💡 **قاعدة د. مايكل الذهبية:** *"جودة نتائج تحليلك لا تعتمد فقط على ذكاء برمجتك، بل تعتمد في المقام الأول على جودة البيانات ومدى ملاءمتها المباشرة لسؤال التحليل الذي تسعى للإجابة عنه!"*

## ⚡ المحور الثالث: واجهات برمجة التطبيقات (APIs) — أنابيب التدفق البرمجي

### 1. ما هي واجهة برمجة التطبيقات (API)؟
كلمة **API** هي اختصار للمصطلح العلمي: **Application Programming Interface** (واجهة برمجة التطبيقات).
* **التعريف المنهجي:** هي مجموعة من القواعد والبروتوكولات التي تتيح لبرنامج معين أن يطلب بيانات أو وظائف من برنامج أو خدمة أخرى تلقائياً.
* **الفارق بين المتصفح و API:**
  - **عبر المتصفح:** تفتح الموقع يدوياً، تضغط أزرار البحث، تقرأ النتائج بعينيك، ثم تنزل ملفاً وتحفظه يدوياً على قرصك الصلب.
  - **عبر API:** يكتب برنامجك سطراً برمجياً يرسل طلباً مباشراً في جزء من الثانية، فتصله البيانات خاماً ويدمجها في قواعد بياناته أو خوارزمياته تلقائياً، دون أي تدخل بشري!

### 2. دورة الطلب والاستجابة الثلاثية (The 3-Step Request-Response Lifecycle)
يوضح كتاب الوزارة (ص 122 - الشكل 5.3.1) المسار الحتمي لأي اتصال عبر API عبر ثلاث خطوات متتالية:

```
        [ العميل - Client ]                                  [ الخادم - Server ]
      (تطبيقك البرمجي أو موقعك)                               (مزود بيانات الطقس أو البنك)
               |                                                         |
               | -------- (1) إرسال الطلب (HTTP Request) --------------> |
               |     إلى نقطة النهاية (Endpoint URL)                      |
               |                                                         |
               |                                                 [ معالجة الطلب ]
               |                                                 (فحص الصلاحيات،
               |                                                  استخراج البيانات)
               |                                                         |
               | <------- (2) إعادة الاستجابة (HTTP Response) ---------- |
               |      (بيانات بصيغة JSON أو رسالة خطأ Error)             |
               |                                                         |
      [ قراءة الاستجابة ]                                                 |
      - استخدام البيانات بنجاح                                            |
      - أو معالجة الخطأ بذكاء                                             |
```

1. **الخطوة الأولى — إرسال الطلب (Request):**
   - يرسل **العميل (Client)** — وهو برنامجك أو تطبيقك — طلباً عبر الشبكة إلى **نقطة النهاية (Endpoint)**.
   - **ما هي نقطة النهاية (Endpoint)؟** هي عنوان ويب محدد (URL) داخل الـ API مخصص لاستقبال نوع معين من الطلبات (مثلاً: `https://api.weather.com/v1/forecast/cairo`).
2. **الخطوة الثانية — معالجة الطلب وإعادة الاستجابة (Response):**
   - يستقبل **الخادم (Server)** الطلب، يتحقق من صلاحيته، يعالج البيانات المطلوبة، ثم يعيد استجابة رقمية (Response) تحتوي البيانات المطلوبة بصيغة قياسية (مثل **JSON**)، أو رسالة خطأ توضح سبب التعذر (مثل تجاوز عدد الطلبات أو خطأ في العنوان).
3. **الخطوة الثالثة — قراءة الاستجابة والتعامل معها (Client Handling):**
   - يقرأ برنامج العميل تلك الاستجابة؛ فإذا كانت ناجحة استخرج البيانات منها وشغّل تحليلاته، وإذا تضمنت رسالة خطأ تعامل معها البرنامج بحذر (مثلاً بإعادة المحاولة لاحقاً أو إبلاغ المستخدم).

## 📦 المحور الرابع: صيغة JSON — اللغة العالمية لتبادل البيانات

### 1. ما هي صيغة JSON؟
هي اختصار لـ **JavaScript Object Notation** (تدوين كائنات جافا سكريبت).
* **طبيعتها:** هي صيغة نصية خفيفة (Lightweight Text Format) وسهلة القراءة للبشر والآلات على حد سواء، مخصصة لتمثيل البيانات المهيكلة.
* **بنيتها الأساسية:** تعتمد على مبدأ **الاسم / القيمة (Key / Value Pairs)**، وتستخدم:
  - **الأقواس المعقوفة `{}`** لتمثيل الكائنات (Objects).
  - **الأقواس المربعة `[]`** لتمثيل المصفوفات والقوائم (Arrays).
  - النقطتين الرأسيتين `:` للفصل بين المفتاح وقيمته.
  - الفاصلة `,` للفصل بين العناصر.

### 2. نموذج واقعي لاستجابة JSON (تطبيق الطقس في القاهرة):
```json
{
  "city": "Cairo",
  "country": "Egypt",
  "timestamp": "2026-09-10T12:00:00Z",
  "weather": {
    "temperature_celsius": 31.5,
    "humidity_percent": 42,
    "condition": "Sunny"
  },
  "forecast_next_days": [
    { "day": "Friday", "temp": 32 },
    { "day": "Saturday", "temp": 30 }
  ]
}
```

> ⚠️ **ملاحظة امتحانية دقيقة (ص 122):**
> صيغة JSON هي الصيغة الأكثر شيوعاً وشهرة في واجهات برمجة التطبيقات الحديثة، **لكنها ليست الصيغة الوحيدة!** فقد تدعم بعض الأنظمة صيغاً أخرى مثل XML أو CSV بحسب تصميم الخدمة.

## 🛑 المحور الخامس: حدود الاستخدام وميثاق الشرف الأخلاقي (Rate Limits & Policies)

### 1. هل الوصول عبر API يمنحك مطلق الحرية؟
**قطعاً لا!** يشدد كتاب الوزارة (ص 122 و 126) على المبادئ التالية:
1. **الوصول عبر API لا يلغي أبداً شروط الاستخدام أو التراخيص:** فإذا كان الترخيص يمنع الاستخدام التجاري أو يلزم بنسب العمل لصاحبه، فإن جلبك للبيانات عبر سطر كود Python لا يعفيك إطلاقاً من الالتزام بهذه الشروط.
2. **حدود الطلبات (Rate Limits):** الخوادم التي تقدم خدمات API تمتلك موارد حوسبية محددة. لذا تفرض الشركات قيوداً على عدد الطلبات المسموح بها (مثلاً: 100 طلب في الدقيقة).
   - **الخطر الهندسي:** إرسال طلبات مفرطة في وقت زمني قصير قد يؤدي إلى حظر عنوانك التقني (IP Banning) أو تعطل الخدمة. لذلك يجب على المهندس المحترف برمجة فترات انتظار ذكية وتجنب إغراق الخادم بالطلبات.
3. **سياسات التخزين والنشر (Caching & Redistribution Policies):** بعض مزودي الـ APIs يمنعونك من حفظ نسخ دائمة من بياناتهم على خادمك الخاص (No Persistent Caching)، أو يمنعونك من إعادة بيع البيانات الخام.

## ✍️ المحور السادس: الاستشهاد العلمي والإسناد الأكاديمي (Attribution & Citation)

### 1. لماذا نذكر المصدر دائماً؟
عندما تبني تحليلاً أو ترسم رسماً بيانياً باستخدام بيانات مفتوحة، يفرض عليك العرف العلمي والتربوي **الإشارة الصريحة للمصدر (Attribution)** وفق الطريقة التي يحددها الترخيص.

### 2. العناصر الأربعة للاستشهاد المتكامل (ص 123):
لكي يكون استشهادك احترافياً وكاملاً، يجب أن يتضمن العناصر الأربعة الآتية:
1. **الجهة الناشرة أو المزود (Publisher / Provider):** مثل "البنك الدولي (World Bank)".
2. **اسم مجموعة البيانات (Dataset Name):** مثل "مؤشرات التنمية العالمية (World Development Indicators)".
3. **تاريخ الإصدار أو تاريخ الوصول (Publication Date / Access Date):** لأن البيانات المفتوحة تتحدث باستمرار، فيجب توثيق متى حصلت عليها بالتحديد (مثلاً: سبتمبر 2026).
4. **رابط المصدر الدائم (URL / Source Link):** الرابط الإلكتروني المباشر الذي يقود إلى صفحة البيانات الأصلية أو نقطة النهاية للتحقق منها.

### 3. الصدمة الإحصائية: هل ذكر المصدر يثبت دقة البيانات؟
ضع تحت هذه العبارة خطاً أحمر عريضاً:
> ❌ **خطأ شائع:** *"بما أنني ذكرت أن البيانات مأخوذة من موقع شهير، فإن أرقامي معصومة من الخطأ وموثوقة بنسبة 100%!"*
> 
> ✅ **الحقيقة المنهجية الصارمة (كتاب الوزارة ص 123):**
> **«إن مجرد ذكر المصدر وحده لا يثبت موثوقية البيانات! بل إن فائدته تكمن في مساعدة الآخرين على العثور على البيانات ومراجعة تحليلك وتكراره. وتبقى جودة البيانات ومنهجية جمعها في حاجة دائمة إلى تقييم علمي مستقل!»**

### 3. حل نشاط "فكر كمهندس: ابحث ثم قرر" (ص 125)
* **المهمة الهندسية:** *"مشروع مدرسي لإظهار كيف تغير الوصول إلى الإنترنت في مصر خلال السنوات العشر الماضية مقارنة بدولتين مجاورتين."*
* **التحليل الهندسي الشامل لد. مايكل:**
  1. **فحص المرشحين:**
     - **World Bank Open Data:** يحتوي على مؤشر معتمد ودقيق يُدعى (Individuals using the Internet % of population) ممتد لجميع دول العالم عبر عقود زمنية سنوية منتظمة ومحدثة.
     - **UN Data:** يحتوي على بيانات الاتصالات وتكنولوجيا المعلومات عبر الاتحاد الدولي للاتصالات (ITU) المرفوعة على بوابة الأمم المتحدة.
  2. **المقارنة بين المصدرين:** كلاهما موثوق، ولكن بوابة البنك الدولي تتميز بوجود واجهة برمجة تطبيقات (API) سهلة التنزيل المباشر بصيغ CSV و JSON وتوفر مقارنة بصرية مسبقة الصنع عبر السلاسل الزمنية للدول الثلاث في جدول واحد موحد.
  3. **الخطر الهندسي لاختيار المصدر الخاطئ:** إذا اخترت مصدراً غير موثوق أو اعتمدت على تدوينات عامة، فقد تكون تعريفات "الوصول للإنترنت" متباينة (مثلاً: من فتح الإنترنت مرة شهرياً مقابل اشتراكات النطاق العريض الثابت)، مما يقود إلى مقارنة مضللة وظالمة وتشويه النتائج.
  4. **صياغة الاستشهاد المعياري:**
     - **المزود:** World Bank Open Data.
     - **اسم المجموعة:** World Development Indicators - Individuals using the Internet (% of population).
     - **الرابط:** `https://data.worldbank.org/indicator/IT.NET.USER.ZS`
     - **تاريخ الوصول:** سبتمبر 2026.

### 4. حل تدريب "طبق ما تعلمته" (ص 125)
* **المسألة:** *"تطبيق طقس يعرض توقعات اليوم من خدمة عامة. صف الطلب والاستجابة بين التطبيق والخادم، واذكر صيغة بيانات محتملة."*
* **الحل النموذجي:**
  - **الطلب (Request):** يقوم تطبيق الطقس (العميل) بإرسال طلب HTTP GET إلى نقطة النهاية (Endpoint) التابعة لمزود الخدمة، حاملاً الإحداثيات أو اسم المدينة (مثلاً: `https://api.open-meteo.com/v1/forecast?latitude=30.04&longitude=31.23&current_weather=true`).
  - **الاستجابة (Response):** يعالج خادم مزود الطقس الطلب، ويعيد استجابة رقمية بحالة نجاح (200 OK) محملة بحزمة بيانات نصية بصيغة **JSON**.
  - **صيغة البيانات المحتملة:** صيغة **JSON** (JavaScript Object Notation)، مع التنبيه إلى أن صيغة البيانات تعتمد على تصميم الخدمة وقد تكون في بعض الأنظمة الأخرى بصيغة XML.
  - **التعامل:** يفكك التطبيق كائن JSON، ويستخرج درجة الحرارة وسرعة الرياح ليعرضها على شاشة الهاتف بصورة بصرية جذابة للمستخدم.

### 5. حل تمرين ملء الفراغات المنهجي (ص 126)
1. يمكن العثور على مؤشرات دولية في بوابات مثل **(UN Data أو World Bank Open Data)**، مع فحص تعريف المؤشر ومصدره.
2. قد يوفر المصدر **(API / واجهة برمجة تطبيقات)** ليتلقى البرنامج استجابة.
3. بصيغة مثل **(JSON)** بحسب الخدمة.
4. ويجب دائماً التحقق من **(شروط الاستخدام / التراخيص)** الخاصة بالمجموعة.
5. ثم تقديم **(الإشارة إلى المصدر / الاستشهاد / Attribution)** إلى المصدر وفق الترخيص ومعيار الاستشهاد.
